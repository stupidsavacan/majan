# オフライン三麻

オフライン三麻は、ブラウザだけで動くオフライン専用の一人用三麻ゲームです。プレイヤーは人間1人で、CPU 2人を相手にローカル環境で対局します。現在の実装は、HTML・CSS・ブラウザJavaScriptで構成されており、実行時にサーバー、アカウント、CDN、オンライン対戦サービス、ネットワーク通信は必要ありません。

プレイ画面は基本的に日本語です。ソースファイル名、保存キー、診断表示、一部の古いドキュメントには、まだ `Phase` という歴史的な名前が残っています。これは過去の実装区分の名残であり、現在の仕様や今後の予定をそのまま表すものではありません。

## 現在の状態

- 人間1人 + CPU 2人のローカル三麻卓としてプレイできます。
- 通常の入口はリポジトリ直下の `index.html` です。
- 正本アプリコピーは `extracted-zips/offline-sanma-mahjong-phase1/` にあります。root の `index.html` は、この正本コピーを参照しつつ、root から見たパスに合わせてスクリプトやアセットを読み込みます。
- 実行時はオフライン前提で、外部アセットの取得は行いません。
- ゲーム状態、設定、牌譜、成績はブラウザの `localStorage` に保存されます。
- CPU はヒューリスティック方式です。シャンテン推定、可視牌カウント、簡易的な手牌価値・危険度評価、押し引きモードを使いますが、強い麻雀AIや完全なAIではありません。

## 起動方法

リポジトリ直下の `index.html` をブラウザで開いてください。

```text
index.html
```

ローカルの静的サーバーを使って開いても構いません。たとえば、リポジトリ直下で以下を実行します。

```bash
python3 -m http.server 8000
```

その後、ブラウザで `http://localhost:8000/` を開きます。

ブラウザゲーム本体にビルド手順はありません。HTML内の script タグから各JavaScriptファイルを読み込む構成です。

## テスト方法

リポジトリ直下で、中央テストランナーを実行します。

```bash
node tests/run-all-tests.js
```

テストは通常のNodeスクリプトです。手牌解析、役判定、点数計算、ルール回帰、UIマスキング、CPU戦略・危険度分析、保存・牌譜・リプレイ、鳴き・カンの流れ、復旧処理、ドキュメント整合性などを検査します。

## 主な機能

- 三人麻雀の局進行と対局進行。
- 人間プレイヤーの打牌、ツモ、ロン、リーチ、カン、北抜き、鳴き選択。
- CPUによる自摸、打牌、ツモ和了、ロン、リーチ、北抜き、カン、実装済みの鳴き。
- 対局形式、北の扱い、チー、ツモ損、赤ドラ、高打点モード、喰いタン、後付け、裏ドラ、槓ドラ、槓裏ドラなどを変更できる設定画面。
- ローカル調査用の固定seedとデバッグ操作。
- 牌譜一覧、詳細表示、リプレイ、成績、JSONエクスポート/インポート、削除、リセットを行える牌譜パネル。
- ブラウザ内SVGによる牌表示。牌画像アセットのダウンロードは不要です。

## 対応しているゲームルール

この実装は、あらゆるローカルルールを切り替えられる完全なルールセレクターではなく、三麻用のルールエンジンです。現在の主な対応範囲は次の通りです。

- 3人対局、初期点35000点。
- 一局戦、東風、半荘。
- 局進行、本場、リーチ棒、連荘、対局終了処理。
- `HandAnalysis` / `TileUtil` による三麻牌構成。通常プレイでは萬子の2〜8を使わない構成です。
- 北の扱い: 北抜きドラ、通常牌、北なし。
- 設定有効時の北抜きと補充牌、北ドラ扱い。
- ツモ損設定。
- 赤ドラと高打点モード。
- 裏ドラ、槓ドラ、槓裏ドラ。
- リーチ、一発、フリテン判定、リーチ後の打牌制限。
- 流局時のテンパイ/ノーテン精算。
- 標準では頭ハネ。ダブロンは `RuleConfig.doubleRonPolicy.allowed` によりコード上は切り替え可能ですが、初期値は無効です。

役・点数計算については、一般的な門前/副露役、ドラ、複数の役満に対応しています。現在のコードには、リーチ、一発、門前清自摸和、断么九、平和、一盃口、二盃口、役牌、七対子、対々和、三暗刻、三槓子、小三元、混老頭、混一色、清一色、一気通貫、混全帯么九/純全帯么九、海底摸月、河底撈魚、嶺上開花、槍槓、天和、地和、国士無双と国士無双十三面待ち、四暗刻と四暗刻単騎、大三元、小四喜、大四喜、字一色、緑一色、清老頭、四槓子、九蓮宝燈/純正九蓮宝燈の判定が含まれます。人和や流し満貫のようなローカル差が大きい役は、通常のゲームプレイ用の役としては基本的に有効化されていません。

## 鳴き・カンの挙動

- ポンは人間プレイヤーとCPUの両方で実装済みです。
- チーは `allowChi` が有効な場合に実装されています。現在の三麻ロジックでは、上家の捨て牌に対してのみ、筒子・索子の順子でチーできます。初期設定ではチーなしです。
- 明槓は、他家の捨て牌に対して合法な明槓候補がある場合に実装されています。
- 暗槓と加槓は、自分の手番中のカン選択として実装されています。
- CPUの通常ロン、槍槓ロン、ポン、チー、明槓は実装済みです。
- 人間用の呼び出し窓には、合法な場合にロン、ポン、チー、明槓、スキップが表示されます。
- 非和了の鳴き優先度は `CallResolver` / `CallFlow` で処理され、カン、ポン、チーの順で優先されます。ロンは別処理です。
- ルールが有効な場合、加槓と暗槓は槍槓で中断される可能性があります。暗槓への槍槓は、コード上実装されている国士無双例外の経路に限られます。
- カン確定時には、設定に応じて槓ドラ表示と嶺上牌の取得が行われます。
- リーチ中のプレイヤーは副露できません。リーチ後の暗槓は、現在のツモ牌を含み、待ちが変わらない場合に限られます。

## CPUの挙動

CPUは単純で透明性を重視した実装です。

- 打牌選択では、通常手、七対子、国士無双のシャンテン推定を使います。
- 打牌候補は、牌姿ヒューリスティック、推定手牌価値、可視牌カウント、推定残り枚数、簡易危険度、押し引きモードで採点されます。
- 可視情報には、CPU自身の手牌、全員の河、公開副露、抜き北、見えているドラ表示牌、現在の直近打牌が含まれます。
- CPUのフェアプレイ処理は可視情報だけを使います。相手の伏せ手牌、生牌山、王牌の中身は、可視牌カウントや危険度分析に使いません。
- 危険度分析では、リーチ者の脅威、親/副露の圧力、現物、筋、壁、字牌、中張牌/端牌、見えている枚数、ドラ表示牌まわり、山の残り具合などを見ます。
- 鳴き判断では、ポン、チー、明槓について、シャンテン、価値、危険度を使った簡易ヒューリスティックを使います。
- CPUは弱い選択や人間らしくない選択をすることがあります。期待値探索AI、防御特化AI、強い麻雀AIではありません。

## アーキテクチャ

アプリはブラウザのグローバル名前空間 `window.Sanma` を使い、HTML内の script タグの読み込み順に依存しています。現在の実行経路にバンドラーはありません。

大まかな構成は次の通りです。

- `GameEngine.js` はメインのエンジン窓口です。現在の局状態を持ち、多くの処理を各Flowモジュールへ委譲します。
- Flowモジュールは、もともと大きかったエンジン責務を分割しています。
  - `RoundLifecycle.js`: 局開始、配牌、牌譜作成、流局精算、対局進行。
  - `TurnFlow.js`: 打牌、CPU手番進行、CPU打牌選択、リーチ、北抜き。
  - `WinFlow.js`: ツモ、ロン、頭ハネ/ダブロン解決、点棒精算、勝者手牌公開。
  - `CallFlow.js`: 人間/CPUの副露、呼び出し窓、スキップ、優先度処理。
  - `KanFlow.js`: カン選択、カン試行、槍槓窓、カン確定。
  - `DrawContext.js`、`RecordFlow.js`、`RecoveryFlow.js`: 補助的な進行処理。
- ルール・解析系は、`RuleConfig.js`、`ActionResolver.js`、`HandAnalysis.js`、`YakuAnalysis.js`、`ScoreCalculator.js`、`Settlement.js`、`RiichiRules.js`、`KanRules.js`、`FuritenManager.js`、`KitaManager.js` などに分かれています。
- CPU専用モジュールは `CpuStrategy.js`、`CpuVisibleTiles.js`、`CpuRiskAnalysis.js` です。
- UI向けの状態マスキングは `UiStateView.js` と `GameEngine.getState()` に集約されています。
- 描画処理は `src/ui/` 配下にあり、主に `renderTable.js`、`renderTiles.js`、`recordPanel.js`、`ReplayViewer.js` が担当します。
- 保存処理は `src/storage/` 配下にあり、`localStorage` を使います。

## 牌譜・保存・リプレイ・成績

- 設定、牌譜、インデックス、成績は、歴史的な `offlineSanma.*` キーでブラウザの `localStorage` に保存されます。
- 牌譜ストアは最新20件を保持します。
- 完了した牌譜は `GameRecordStorage` を通して保存されます。保存失敗時には、ランタイム側で再試行または破棄できる経路があります。
- 牌譜パネルでは、保存牌譜の一覧、詳細確認、エクスポート、インポート、削除、リセットができます。
- `ReplayViewer` は牌譜イベントからリプレイ表示を再構築し、1手進む/戻る、先頭/末尾へ移動、局選択、自動再生に対応します。
- 成績は保存牌譜から計算され、対局単位の成績、局単位の成績、役頻度、役満名、モード別内訳などを表示します。
- インポート牌譜は検証とID衝突回避を通して受け入れられます。ただし、インポートした牌譜は自動的に新規の成績対象対局として扱われるわけではありません。

## デバッグメモ

- デバッグ画面には、現在phase、手番、山残り、和了形判定、役判定、点数計算、利用可能操作、呼び出し窓、副露/抜き北、聴牌判定、ルール設定、CPU鳴きログ、CPU思考ログ、補助ログ、診断、整合性サマリー、tileLedgerサマリー、デバッグイベントが表示されます。
- `GameEngine.getState()` は、通常UIやデバッグ表示向けに隠し情報をマスクします。CPU手牌は伏せ牌数として表示され、CPUのリーチ詳細は簡略化され、生牌山/王牌の生情報は公開されず、`tileLedger` もサマリーだけが表示されます。
- ロン成立時は、`winResult.revealedHand` で勝者の手牌だけを公開します。非勝者CPUの伏せ手牌は隠したままです。
- デバッグ画面から固定seedを設定すると、調査用に再現可能な対局を作れます。
- 保存リセット操作は `offlineSanma.*` の `localStorage` データを削除します。

## 現在の制限

- オンライン対戦はありません。
- サーバー側アカウント、クラウド保存、ランキングサービス、本番級の不正対策はありません。
- CPUはヒューリスティック実装であり、強い麻雀AIや完全な麻雀AIではありません。
- ルール対応は広めですが、完全ではありません。ローカルルールや珍しい変種は、無効・保留・未実装の場合があります。
- ダブロンはコード設定としては存在しますが、通常の設定画面で公開されている公開設定項目ではありません。
- チーは `allowChi` の裏にありますが、三麻の初期設定では無効です。
- ブラウザストレージ容量の制限を受けます。古い牌譜、壊れた牌譜、インポート牌譜、イベントが間引かれた牌譜は、リプレイ表示が一部のみになる場合があります。
- リポジトリには、過去のPhaseドキュメントや古いラベルがまだ残っています。古いアーカイブよりも、このREADME、`docs/`、現在のソースコードを優先してください。

## 開発メモ

- 実行時の本体変更は、特別な理由がない限り `extracted-zips/offline-sanma-mahjong-phase1/` 配下の正本アプリコピーに対して行ってください。
- ブラウザスクリプトを追加・削除する場合は、root `index.html` と正本コピー側 `index.html` の読み込み順を揃えてください。
- 将来予定を現在機能のように書かないでください。コードが実装している内容だけを記録してください。
- 完全なチェックアウト環境がある場合は、変更後に `node tests/run-all-tests.js` を実行してください。
